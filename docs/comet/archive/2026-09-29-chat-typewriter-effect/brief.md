# 目标

聊天区的 AI 流式回复改为打字机式输出：每行逐字写出，行与行之间停顿并显示三点加载气泡，让回复像对方正在输入；积压时加快打字，长回复不会拖得太久。用户可以在设置里关闭这个效果，开关保存到账号，关闭后恢复现在的整行显示。

# 范围

- 前端流式回复的显示方式：逐字节奏（出字速度、追赶、行间停顿、表情 token 整体出现），以及首个字到达前、流结束、用户停止、上游错误帧、生成中切换会话时的显示规则；气泡尺寸随文字增长、虚拟列表测量与自动滚动跟随。
- 设置对话框"AI 配置"新增"打字机效果"开关；后端 `UserSettings` 新增 `typewriter` 字段，`GET / PATCH /api/settings` 支持该字段；后端启动时给缺少该列的旧库自动补列（线上 Neon Postgres 无需手工 SQL）。
- 完整目标规格第 3、7、9、11、12 节同步更新；单元测试、pytest 与 E2E 覆盖新行为。
- 文档：`docs/interview.md` 新增技术亮点（五段式，代码 💡 注释指回）并更新问答；`docs/frontend.md`、`docs/api.md`、`docs/deploy.md`、`docs/notes/measurements.md` 同步；文档中写死的统计重新核对。

# 非目标

- 历史消息、刷新后或切换会话后重新加载的消息不做逐字效果，直接显示。
- 不改变"一行一个气泡"的分段规则，不把整条回复合并成一个气泡。
- 不改后端 SSE 协议、mock 回复的内容与节奏、上下文拼装和停止时的保存规则。
- 不引入 Alembic 等通用迁移工具，只为本次新增的一列做启动补列。
- 不做打字音效、打字光标，不提供出字速度的用户设置。

# 约束与不变量

- 网络请求与流式状态仍由 `chatStore` 管理；逐字节奏只影响显示，不改变发送、停止与持久化的时序；停止或出错时界面立即与持久化结果一致。
- 打字结束后界面上的文字与刷新后从后端读到的消息一致（同样按行、去首尾空白、跳过空行）。
- 已显示完的气泡在打字过程中不重渲染（沿用 `memo(ChatBubble)` 的原始值 props）；虚拟列表只渲染可视区附近的行；接近底部时随打字增长保持在底部，向上浏览时不被拉回。
- 首个字到达前、行与行之间仍显示三点加载气泡。
- 遵守仓库约定：五板斧、函数组件 + Hooks、中文文档注释、emoji 只用 ✅⚠️💡 且每个文件最多 5 个、💡 注释指向 `docs/interview.md` 已有标题。

# 决策

已查明的事实：

- 现状：`chatStore.sendMessage` 用 `takeCompletedLines` 把累积文本按 `\n` 切行，每凑满一整行才追加一个临时气泡，没写完的半行不显示；首个字前和行与行之间显示三点加载气泡。
- 原 Vue 项目的"假打字"不是逐字输出：每行之前先停 0.6–1 秒，再显示 0.9–1.5 秒三点加载动画，然后整行出现（`endfield-baker-chat/src/composables/useAiChat.ts`）。
- 真实 DeepSeek（关闭思考）一条三行、约 80 token 的回复，从首个数据块到全文完成约 0.5 秒（`docs/notes/measurements.md` 9.2）；mock 后端每 80 ms 发 5 个字。
- 后端落库（`backend/app/routers/chat.py` 的 `persist_reply`）：停止或断开时丢弃最后未收完的半行；上游出错时保留已收到的全部文本（含最后一段）并额外保存一条错误消息。
- 表结构靠启动时 `Base.metadata.create_all` 创建（`backend/app/main.py`），没有迁移工具；`create_all` 不会给已存在的表加列。设置对话框的"AI 配置"标签页已有温度与最大 token。

用户决定（2026-09-28）：

- D1（Q1）逐字 + 行间停顿：一行的第一个字到达且轮到该行时出现气泡，文字逐字显示、气泡随之变宽变高；一行写完后停顿并显示三点加载气泡，再在新气泡里写下一行。
- D2（Q2）匀速 + 追赶：平时约每秒 40 字，积压越多写得越快，正在写的内容最多落后网络约 1 秒。
- D3（Q3）停止时半行消失：点"停止"后已完整收到的行立即全部显示（不再逐字、不再停顿），正在写或未收完的半行消失；不改后端保存规则。
- D4（Q4）设置里加开关并保存到账号：后端 settings 新增 `typewriter` 字段，默认开启；关闭后恢复整行显示。
- D5（Q5）停顿固定、只追赶打字：行间固定停顿 0.5 秒并显示加载气泡；追赶只加快打字，停顿不计入落后时间、也不因积压缩短。
- D6（Q6）启动时自动补列：后端启动时检查 `settings` 表，缺少 `typewriter` 列就执行 `ALTER TABLE` 补上（已有用户取默认值开启），SQLite 与 Postgres 都适用，部署无需手工操作。

由上述决定推出、最终确认时可改的默认做法：

- 不显示打字光标，气泡随文字增长本身表明"正在输入"，与原项目和现有设计稿一致。
- 开关放在"AI 配置"标签页，切换后立即保存（与聊天条样式切换一样），不受本页"保存"和"恢复默认"影响；从下一条回复开始生效。
- 系统开启"减少动态效果"（`prefers-reduced-motion: reduce`）时，即使开关开启也整行显示。
- 流结束后还没写完的内容照常写完，写完之前仍显示"停止"按钮、输入框禁用；此时点"停止"则剩余的行立即全部显示。
- 收到错误帧时不再逐字，已收到的全部文本按行立即显示，随后显示错误气泡，与后端出错时的落库内容一致。
- 生成中切换会话时逐字进度照常推进，切回后从当前进度继续，不重播。
