# E2E、CI、Docker 一键启动与线上部署配置（e2e-ci-deploy）

记录 `e2e/`（Playwright）、`.github/workflows/ci.yml`、`docker-compose.yml` + 两个 Dockerfile、`render.yaml` / `frontend/vercel.json` / `docs/deploy.md` 的选型、问题与实测数据。日期 2026-09-24；环境：macOS（Apple Silicon）、Node 22.22.2、pnpm 9.12.0、Python 3.13.5、Docker 28.5.1 / Compose v2.40.2。

## 2. 遇到的问题

### 2.1 webServer 对 Vite 的就绪探测永远收到 502

- 现象：第一次 `pnpm --filter e2e test` 报 `Timed out waiting 60000ms from config.webServer`，但 uvicorn 日志显示 `Application startup complete`。`DEBUG=pw:webserver` 显示：后端 `http://localhost:8020/health` 探测一次即 200；前端 `http://localhost:5180/` 每次探测约 3 秒后 `HTTP Status: 502`，反复直到超时。
- 定位：502 不可能来自 Vite。另起两个服务后用 Node `fetch` 直测：`localhost:5180` 200、`127.0.0.1:5180` ECONNREFUSED、`[::1]:5180` 200；`lsof` 显示 Vite 只监听 `[::1]:5180`，uvicorn 监听 `127.0.0.1:8020`。再查环境：`HTTP_PROXY=http://127.0.0.1:7897`，没有 `NO_PROXY`。
- 根因：Playwright 的探测用 `http.request` 且遵守 `HTTP_PROXY`，请求经本机代理转发；代理把 `localhost` 解析成 127.0.0.1，能连上 uvicorn（IPv4），连不上只监听 IPv6 的 Vite，于是回 502。Node 的 `fetch`（undici）自带 happy-eyeballs，两个地址都试，所以直接 fetch 时看不出问题。
- 修复：两个服务显式 `--host 127.0.0.1`，探测 URL 与 `metadata.backendUrl` 用 `127.0.0.1`；浏览器一侧（`baseURL`、`VITE_API_BASE_URL`）保持 `localhost`。有没有代理都能过，且不依赖 `NO_PROXY`。
- 验证：`DEBUG=pw:webserver` 下前后端各探测一次即 200；套件 2 用例通过。

### 2.2 并行 agent 的半成品让后端起不来

- 现象：`ImportError: cannot import name 'StopOut' from 'app.schemas'`，Playwright 报 `Process from config.webServer was not able to start. Exit code: 1`。
- 定位：`git status` 看到 `backend/app/routers/chat.py`、`app/schemas.py` 有未提交修改，是同时进行的"停止生成"接口任务的中间状态。
- 处理：不碰 `backend/app`，用 `.venv/bin/python -c "import app.main"` 轮询，约 2 分钟后可导入，重跑即过。经验：并行开发时 E2E 起不来先看是不是别人的半成品，不要急着改配置。

### 2.3 `getByText` 严格模式：最后一行同时出现在子卡预览里

- 现象：`getByText('第三行用于验证分段。', { exact: true })` resolved to 2 elements——子卡预览的 `<p>` 和气泡里的 `<div>`。前两行没事。
- 根因：流结束后 `chatStore` 重拉消息并用 `withLastMessage` 更新会话预览，只有最后一行会同时出现在两处；断言跑到第三行时流已经结束。
- 修复：逐行断言限定在气泡文本节点 `svg foreignObject > div` 内：`bubbleTexts.filter({ hasText: line })`；同一个 locator 之后还用于顺序断言 `nth(1..3)`。
- 验证：通过；刷新后反过来利用这一点，用 `getByRole('button', { name: '第三行用于验证分段。' })` 既选中子卡又断言了预览文案。

### 2.4 `docker compose config` 里的 `required: true` 虚惊

- 现象：grep `docker compose config` 输出时看到 `required: true`，怀疑 `env_file` 的 `required: false` 没生效（当时 `backend/.env` 不存在）。
- 定位：完整输出里 `env_file` 段已被 compose 展开消失，`required: true` 属于 `depends_on` 的规范化字段。再用一个没有 `backend/.env` 的空目录做 `--project-directory` 跑 `docker compose config`，成功解析，证明缺文件时不报错。
- 结论：配置正确；`backend/.env` 在 15:03 被别的会话创建（含 DEEPSEEK_API_KEY 等），compose 会整体传入容器，但 `environment` 里的 `AI_MOCK` / `JWT_SECRET` / `CORS_ORIGINS` / `DATABASE_URL` 优先，所以默认仍是 mock；要用真实 Key 需 `AI_MOCK=0 docker compose up`。

## 4. 留给主会话 / 其他 agent 的注意点

- 新增了根目录 `.dockerignore`（任务清单没列，但前端镜像以仓库根为上下文时必需，否则两个旧项目和 node_modules 都会进构建上下文）。
- CI 没有在 GitHub 上实际跑过（无 act）：首次 push 后看 Actions；最可能出问题的是 e2e job（`python -m uvicorn` 依赖 `pip install -e backend` 装进 setup-python 的解释器；`playwright install --with-deps chromium` 需要 sudo，ubuntu runner 自带）。
- `e2e/.tmp/e2e.db` 在运行后保留、下次启动前删除，已在 `e2e/.gitignore`。
- Playwright 精确锁 1.62.1；升级版本时本机要重新 `pnpm --filter e2e exec playwright install chromium`。
- `render.yaml` 里 `CORS_ORIGINS` 的占位是 `https://baker-chat.vercel.app`，部署后按 Vercel 实际域名改（deploy.md 第 (d) 步）。
- 主卡 / 子卡的可访问名：主卡 = 角色名；子卡 = 预览文案（空会话按性别"和他聊聊 / 和她聊聊"，有消息后是最后一条消息文本）。后续 E2E 用例可直接 `getByRole('button', { name, exact: true }).dispatchEvent('click')`。
